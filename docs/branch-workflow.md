# 分支与版本发布

| 分支 | 用途 | 合并方向 |
| --- | --- | --- |
| `main` | 正式版本，只接收已经共同验收的改动。 | `develop` → `main` |
| `develop` | 共同开发与测试分支，集中合并个人成果并验证完整游戏。 | 个人分支 → `develop` |
| `wxb` | WXB 的个人开发分支，从 `develop` 建立。 | `wxb` → `develop` |
| 另一位开发者的个人分支 | 由本人从 `develop` 创建并命名。 | 个人分支 → `develop` |

1. 开发者从最新的 `develop` 开始工作，在自己的分支提交并推送。各自在不同文件或独立工作树中工作，共用文件先沟通。
2. 开 PR 合入 `develop`，说明改了什么、怎么验证，以及还有什么未验证。解决冲突后，在合并后的版本上重新验证受影响的功能。
3. 用同一候选版本验证正常开档、主要玩法、保存读取和基本操作，记录已知问题。通过后由 `develop` 向 `main` 开发布 PR；正式版从审核通过的 `main` 提交构建。

日常开发通过 PR 合并。不要直接将未验收的测试版推到 `main`，也不要强推共享分支。测试存档、账户凭据、Godot 缓存和本机导出目录不纳入常规提交；发布用的 Windows 安装包或压缩包独立于源码分支管理。

首次导入以远程 `main` 为基线，只新增 Godot 工程和协作说明。Godot 测试版启动方式见 [README](../README.md)。
